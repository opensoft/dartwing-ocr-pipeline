# Implementation Plan: PPStructureV3 Module And Model Reduction

**Branch**: `017-ppstructurev3-module-reduction` | **Date**: 2026-05-09 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/017-ppstructurev3-module-reduction/spec.md`

## Summary

Reduce `ppstructurev3@gpu` preprocessing cost on the stage 1 vendor-identity lane by introducing **two named, closed-vocabulary preset axes** — `module_set_id` (PPStructureV3 sub-module preset) and `det_rec_variant_id` (PaddleOCR detection/recognition pairing) — both selectable per run via explicit CLI flags with env-var fallbacks (mirroring feature 016's `--gpu-warmup` precedent). The feature ships a live-path module audit (FR-001) whose result lands on **two surfaces**: an additive `ppstructure_modules_invoked` list field on every `run_summary` line (per Clarifications session 2026-05-09 Q3) AND a richer narrative + raw-trace capture in this feature's `research.md` Appendix B at landing time. Two preset axes × on-disk benchmark of ≥2 lighter det/rec variants vs the legacy default on a fixed 5-document corpus subset produces the quality-gate evidence required by FR-015 / SC-008 (per Clarifications Q1: BOTH (a) the per-corpus aggregate vendor-identity field score from `evaluation_run_summary.json` AND (b) the per-document pass count must be ≥ legacy's values on the same subset). Activation surfaces are `--module-set <id>` and `--det-rec-variant <id>` CLI flags (with `LEDGERLINC_MODULE_SET=<id>` / `LEDGERLINC_DET_REC_VARIANT=<id>` env-var fallbacks); CLI wins when both are set. Combining either flag with `ppstructurev3@cpu` or any stub adapter emits a clear stderr warning (FR-013 warn-and-proceed pattern, identical structure to feature 016 FR-010) and otherwise produces a run identical to one without the flag. Selecting an unknown identifier value (e.g., `--module-set reduced-v99`) fails fast with exit code 16 and a clear stderr message (R-017.12 below). The `RunSummary.SCHEMA_VERSION` codebase-level patch bumps **0.1.3 → 0.1.4** for three additive top-level fields (`module_set_id`, `det_rec_variant_id`, `ppstructure_modules_invoked`); the four canonical stage 1 artifact schemas, `contract_set_version`, and `pipeline_version` shape are unchanged (FR-019 / FR-021 / SC-010). Preset resolution is GPU-only on its effects — the CPU singleton in `preprocessing/ocr.py` and the stub adapter retain their existing hard-coded module-disable kwargs and emit `module_set_id = "cpu-default"` / `det_rec_variant_id = "cpu-default"` (or `stub-default` from a stub adapter) per FR-010, so absence of either field on `run_summary` is itself a regression signal. All feature 014 / 015 / 016 guarantees (single-engine-per-process, GPU-readiness probed at most once, single-device guard, no silent CPU fallback after `ppstructurev3@gpu` is selected, warmup behavior under `--gpu-warmup` unchanged, `pipeline_version` ends in `.gpu0`/`.cpu0`) carry over unchanged. Corpus baselines and `preprocess_output.json` shape are byte-identical to `main` for the legacy GPU configuration (FR-018 / SC-006 / SC-007). GPU verification of FR-001 / FR-005 / FR-008 / FR-015 may be deferred per FR-024 (feature 016 precedent); the deferral is captured in `tasks.md` and `quickstart.md` Appendix A so the verification cannot be quietly skipped.

## Technical Context

**Language/Version**: Python 3.12 (matches `.devcontainer/Dockerfile` base image and `pyproject.toml requires-python = ">=3.12"`).
**Primary Dependencies**: existing only — `paddleocr>=3.5,<4` (the `PPStructureV3` constructor already exposes `use_table_recognition` plus `text_detection_model_name` / `text_recognition_model_name` kwargs that this feature drives via the new presets), `paddlepaddle-dcu` (workstation-only optional install, already proven in features 014–016), `pypdfium2>=4.30,<5`, `Pillow>=10.4,<11`, `numpy>=1.26,<3`, `jsonschema>=4.22,<5`, `pydantic>=2.7,<3`. **No new pinned dependency.** The det/rec model weights for the lighter variants ship inside the existing PaddleOCR weight-download flow — no new wheel / no new download host (R-017.4).
**Storage**: filesystem only. Reads `tests/stage1_vendor_identity/inv_XXX_<difficulty>/source.pdf` (unchanged). Writes `preprocess_output.json` into the same per-document folder unchanged in shape (FR-003 / FR-019). The three new run_summary fields live exclusively in the existing `kind: "run_summary"` stdout line per feature 014/015/016 lineage; **no new persisted artifact** (FR-020 / SC-002 / Out of Scope subsection). The benchmark numbers and FR-001 audit narrative land in this feature's `research.md` Appendix B (audit) and quickstart.md Appendix A (benchmark numbers); both are Markdown documents under `specs/017-ppstructurev3-module-reduction/`, not under `contracts/` and not under `tests/stage1_vendor_identity/`.
**Testing**: pytest. Existing markers `gpu` (deselected without GPU per FR-022) and `live` carry over. New tests under `tests/unit/preprocessing/` and `tests/pipeline_tests/` (matching feature 016's directory convention; tasks.md is normative for exact file paths); existing `tests/contract_tests/` continue to pass unchanged (FR-019). Stub-adapter test suites must continue to pass without GPU (FR-014 / FR-023 / SC-005). The warn-and-proceed path for both new switches is covered on the default (no-GPU) suite per FR-023.
**Target Platform**: Linux (devcontainer + workstation WSL with native ROCm `gfx1151` via host Ollama / `.venv-paddle-rocm`). CPU fallback works on any Linux host. Production CI exercises CPU + stub only.
**Project Type**: single Python package (`ledgerlinc-ocr`) with pluggable preprocess profiles. **One new module** (`preprocessing/presets.py`), **one new exception** (`UnknownPresetError` in `preprocessing/errors.py`), and **surgical edits to seven existing modules** (`preprocessing/ocr.py`, `preprocessing/preflight.py`, `preprocessing/cli.py`, `preprocessing/identifiers.py`, `pipeline/timing.py`, `pipeline/corpus_run.py`, `pipeline/runner.py`, `pipeline/cli.py`).
**Performance Goals**: no numeric latency target (Constitution: "no latency target as a release gate"; spec Assumptions). Outcomes are observability + reduction in module-set count + reduction in det/rec inference cost — measurable as (a) `ppstructure_modules_invoked` is strictly a subset on `reduced-v1` vs `legacy` runs of the same fixture (SC-001); (b) at least two lighter det/rec variants are benchmarked and recorded in research with both quality metrics (SC-002); (c) `module_set_id` and `det_rec_variant_id` differ across configurations and remain stable within a configuration (SC-003).
**Constraints**:
- FR-001: live-path audit (instrumentation on the active runtime path, NOT preflight) lands on TWO surfaces — `run_summary.ppstructure_modules_invoked` (every run) AND `research.md` Appendix B (landing-time legacy-vs-reduced narrative).
- FR-002: closed-vocabulary `module_set_id` — only `legacy`, `reduced-v1`, `cpu-default`, `stub-default` are valid at landing; runtime per-sub-module toggling is forbidden.
- FR-005 / FR-006: ≥2 lighter det/rec variants benchmarked on the same fixed corpus subset; legacy variant remains a permanently selectable option.
- FR-007: selecting a configuration whose model weights or runtime fail to bind on GPU MUST fail fast (no silent CPU fallback), preserving feature 015 FR-008.
- FR-008 / FR-010: three additive top-level run_summary fields (`module_set_id`, `det_rec_variant_id`, `ppstructure_modules_invoked`) emitted on every run including CPU/stub.
- FR-009: additive only; no existing `run_summary`, `phase_timings.*`, or `preprocess_output.json` field is renamed/removed/retyped.
- FR-013: GPU-only switches set on CPU/stub follow the warn-and-proceed pattern (warn + no behavior change + same exit status), matching feature 016 FR-010 for `--gpu-warmup`.
- FR-014: CPU and stub paths MUST NOT import GPU-only preset-resolution code; imports are guarded so a host without Paddle GPU runs the default suite cleanly.
- FR-015 (per Clarifications Q1): quality-gate metric is the two-metric gate — aggregate vendor-identity field score from `evaluation_run_summary.json` AND per-document pass count, both measured on the same fixed corpus subset, both ≥ legacy on that subset.
- FR-019: schema_version of the four canonical stage 1 artifacts and `contract_set_version` unchanged.
- FR-021: feature 014/015/016 guarantees preserved unchanged.
- FR-024: GPU verification deferral allowed per feature 016 precedent; deferral captured in `tasks.md` + `quickstart.md`.
- Constitution I: pipeline / harness / model-runtime boundaries intact (this feature touches preprocessing + pipeline runtime only; harness untouched; model runtime — Ollama — untouched).
- Constitution II: four canonical artifact contracts unchanged. Run_summary is run-level observability, not a stage 1 artifact contract — additive bump 0.1.3 → 0.1.4 follows the established additive pattern from feature 014 (0.1.0 → 0.1.1), feature 015 (0.1.1 → 0.1.2), and feature 016 (0.1.2 → 0.1.3).
- Constitution V: corpus baselines must not be regenerated (FR-018 / SC-006).

**Scale/Scope**: stage 1 corpus = 20 documents under `tests/stage1_vendor_identity/`. Benchmarking subset = 5 fixed documents pinned in R-017.11 (`inv_001_easy`, `inv_002_easy`, one mid-difficulty, two challenging). Single GPU-capable workstation host. Single device per process (feature 014 CF4 / feature 015 FR-006 carry over). Two named module-set presets (`legacy`, `reduced-v1`); three named det/rec variants (`legacy` + two lighter; specific lighter names pinned in R-017.4).

**Structure Decision**: single Python package, **one new module** (`preprocessing/presets.py`), **one new error type** (`UnknownPresetError` in `preprocessing/errors.py`), **one new exit code** (`ExitCode.UNKNOWN_PRESET = 16` in `pipeline/exit_codes.py` — immediately after feature 016's exit code 15), **eight touched modules** (`preprocessing/ocr.py`, `preprocessing/preflight.py`, `preprocessing/cli.py`, `preprocessing/identifiers.py`, `pipeline/timing.py`, `pipeline/corpus_run.py`, `pipeline/runner.py`, `pipeline/cli.py`). **No new top-level subpackage.** The preset axes contract lives entirely under `preprocessing/presets.py` (the closed-vocabulary registries plus their audit-callable hook), keeping the run_summary schema as the single source of truth for run-level observability. The `--module-set` and `--det-rec-variant` opt-ins live in the existing preprocess CLI and warm-corpus CLI rather than a new entry point, mirroring how feature 014 added `--preprocess-profile` and feature 016 added `--gpu-warmup` rather than spinning up separate CLIs.
