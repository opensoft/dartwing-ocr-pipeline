# Implementation Plan: DPI Reduction And Region-First Vendor Identity Preprocess

**Branch**: `018-dpi-region-first-preprocess` | **Date**: 2026-05-10 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/018-dpi-region-first-preprocess/spec.md`

## Summary

Reduce `ppstructurev3@gpu` preprocessing latency on the stage 1 vendor-identity lane by introducing **two named, closed-vocabulary preset axes** — `raster_profile_id` (rasterization DPI preset) and `region_strategy_id` (page-area-targeting preset) — both selectable per run via explicit CLI flags with env-var fallbacks (mirroring feature 014's `--preprocess-profile`, feature 016's `--gpu-warmup`, and feature 017's `--module-set` / `--det-rec-variant` precedent). The feature ships at landing two GPU-only DPI presets (`legacy` = 300 DPI per `preprocessing/version.py:16`, `reduced-v1` = 200 DPI per R-018.3) and two GPU-only region-strategy presets (`full-page` = today's edge-to-edge behavior, `header-first-v1` = page-1 top-30%-of-height band only with deterministic fallback to full-page on no-evidence per R-018.5/R-018.7); plus identity presets `cpu-default` and `stub-default` on both axes. The feature ships **three additive top-level fields on `run_summary`** (`raster_profile_id`, `region_strategy_id`, `region_strategy_fallback_count`) emitted on every run including CPU and stub (FR-008/FR-009/FR-011 plus Clarifications Q4 always-emit). The codebase-level `RunSummary.SCHEMA_VERSION` patches **0.1.4 → 0.1.5** for the three additive top-level fields; the four canonical stage 1 artifact schemas, `contract_set_version`, and the `pipeline_version` shape are unchanged (FR-019 / FR-020 / SC-011). Activation is `--raster-profile <id>` and `--region-strategy <id>` on both `python -m dartwing_ocr.preprocessing` and `python -m dartwing_ocr.pipeline` with env-var fallbacks `DARTWING_RASTER_PROFILE` / `DARTWING_REGION_STRATEGY` (CLI wins when both are set, R-018.1). Combining either flag with `ppstructurev3@cpu` or any stub adapter emits a clear stderr warning (FR-014 warn-and-proceed pattern, identical structure to feature 016/017 precedent) and otherwise produces a run identical to one without the flag. Selecting an unknown identifier value (e.g., `--raster-profile reduced-v99` or `--region-strategy header-first-v99`) fails fast with **the existing exit code 16** (`UNKNOWN_PRESET`) and a clear stderr message — the existing `UnknownPresetError` from feature 017 is extended additively (its `preset_axis: Literal[...]` gains `"raster_profile"` and `"region_strategy"`); R-018.12 covers the wiring. The FR-007 region-first → full-page fallback path (Clarifications Q1) is implemented deterministically: after region-first preprocessing of page 1's targeted band, if the whitespace-stripped concatenation of `blocks[].text` in the targeted region is empty (Clarifications Q3 trigger), the partial output is discarded and the document is re-preprocessed under the full-page strategy on the same engine instance (preserving feature 015 FR-001 single-engine guarantee — R-018.9), the document's per-document `phase_timings.rasterization` reports the combined wall-clock cost (region-first attempt + full-page) per R-018.10, and the run-level `region_strategy_fallback_count` is incremented by exactly 1 for that document. On multi-page invoices the `header-first-v1` preset processes page 1's header band only; pages 2..N appear in `preprocess_output.json.pages[]` as empty page records (`page_number`/`width`/`height`/`rotation_detected` derived from PDF page geometry; `blocks: []`, `raw_ocr_lines: []`) so the `pages.length == page_count` invariant is preserved (Clarifications Q2 / R-018.6). Bounding-box coordinates from page 1's cropped band are translated back to full-page coordinates so `preprocess_output.json` field shape and coordinate origin/units/page index/block index stay identical to legacy under FR-002 (R-018.15). All feature 014 / 015 / 016 / 017 guarantees (single-engine-per-process, GPU-readiness probed at most once, single-device guard, no silent CPU fallback after `ppstructurev3@gpu` is selected, warmup behavior under `--gpu-warmup` unchanged, `pipeline_version` ends in `.gpu0`/`.cpu0`, feature 017's `module_set_id` / `det_rec_variant_id` / `ppstructure_modules_invoked` semantics unchanged) carry over unchanged (FR-022). Corpus baselines and `preprocess_output.json` shape are byte-identical to `main` for the legacy `(legacy, full-page)` GPU configuration (FR-019 / SC-007 / SC-008). The four-corner benchmark (FR-005) — `(legacy DPI × full-page)`, `(reduced-v1 DPI × full-page)`, `(legacy DPI × header-first-v1)`, `(reduced-v1 DPI × header-first-v1)` — runs over the **same fixed 5-document subset that feature 017 used** (`inv_001_easy`, `inv_002_easy`, plus three from R-017.11; R-018.13) and lands its numbers in this feature's `quickstart.md` Appendix A. Quality-gate evidence (FR-016 / FR-017) — both metrics from the existing evaluator (per-corpus aggregate vendor-identity field score from `evaluation_run_summary.json` AND per-document pass count per `docs/stage1-vendor-identity/scoring.md`) — lands in this feature's `research.md` Appendix B alongside the candidate `(raster_profile_id, region_strategy_id)` pair. GPU verification of FR-005 / FR-016 / GPU-marked tests may be deferred per FR-025 (feature 016/017 precedent); the deferral is captured in `tasks.md` and `quickstart.md` Appendix B so the verification cannot be quietly skipped.

## Technical Context

**Language/Version**: Python 3.12 (matches `.devcontainer/Dockerfile` base image and `pyproject.toml requires-python = ">=3.12"`).
**Primary Dependencies**: existing only — `paddleocr>=3.5,<4`, `paddlepaddle-dcu` (workstation-only optional install, already proven in features 014–017), `pypdfium2>=4.30,<5` (used for the per-page geometry read on skipped pages 2..N — no rasterization required to obtain `width_pt`/`height_pt`/`rotation`, R-018.6), `Pillow>=10.4,<11` (used for the page-1 header-band crop, R-018.5), `numpy>=1.26,<3`, `jsonschema>=4.22,<5`, `pydantic>=2.7,<3`. **No new pinned dependency.** The `header-first-v1` preset uses `pypdfium2` page geometry and a `Pillow` `Image.crop` call after rasterization — both already on the dependency tree.
**Storage**: filesystem only. Reads `tests/stage1_vendor_identity/inv_XXX_<difficulty>/source.pdf` (unchanged). Writes `preprocess_output.json` into the same per-document folder unchanged in shape (FR-002 / FR-020). The three new `run_summary` fields live exclusively in the existing `kind: "run_summary"` stdout line per feature 014/015/016/017 lineage; **no new persisted artifact** (FR-021 / Out of Scope). The benchmark numbers and FR-001 audit narrative land in this feature's `quickstart.md` Appendix A (benchmark numbers) and `research.md` Appendix B (quality-gate evidence) at landing time; both are Markdown documents under `specs/018-dpi-region-first-preprocess/`, not under `contracts/` and not under `tests/stage1_vendor_identity/`.
**Testing**: pytest. Existing markers `gpu` (deselected without GPU per FR-023) and `live` carry over. New tests under `tests/unit/preprocessing/` and `tests/pipeline_tests/` (matching feature 016/017's directory convention; `tasks.md` is normative for exact file paths). Existing `tests/contract_tests/` continue to pass unchanged (FR-020). Stub-adapter and CPU-only suites must continue to pass without GPU (FR-015 / FR-024 / SC-006). The warn-and-proceed paths for both new switches are covered on the default (no-GPU) suite per FR-024.
**Target Platform**: Linux (devcontainer + workstation WSL with native ROCm `gfx1151` via host Ollama / `.venv-paddle-rocm`). CPU fallback works on any Linux host. Production CI exercises CPU + stub only.
**Project Type**: single Python package (`dartwing-ocr`) with pluggable preprocess profiles. **Two new modules** (`preprocessing/raster_profiles.py`, `preprocessing/region_strategies.py`), **one extended exception** (`UnknownPresetError.preset_axis: Literal[…]` widens to four values), **zero new exit codes** (reuses feature 017's `UNKNOWN_PRESET = 16`), and **surgical edits to nine existing modules** (`preprocessing/rasterize.py`, `preprocessing/pipeline.py`, `preprocessing/cli.py`, `preprocessing/preflight.py`, `preprocessing/identifiers.py`, `preprocessing/errors.py`, `pipeline/timing.py`, `pipeline/cli.py`, `pipeline/runner.py`, `pipeline/corpus_run.py`).
**Performance Goals**: no numeric latency target (Constitution: "no latency target as a release gate"; spec Assumptions). Outcomes are observability + measurable reduction in rasterization cost (per-document `phase_timings.rasterization`) and per-page inference cost (`per_page_inference`) — measurable as (a) `phase_timings.rasterization` strictly lower on `reduced-v1` DPI vs `legacy` for the same fixture (SC-001/SC-003); (b) the four-corner matrix is benchmarked and recorded with both quality metrics (SC-003); (c) `raster_profile_id` and `region_strategy_id` differ across configurations and remain stable within a configuration (SC-004); (d) `region_strategy_fallback_count` is non-negative and reproducible across runs of the same `(raster_profile_id, region_strategy_id)` × corpus subset (Clarifications Q4 / determinism checklist CHK026).
**Constraints**:
- FR-001 / FR-004: closed-vocabulary `raster_profile_id` (`legacy`, `reduced-v1`, `cpu-default`, `stub-default`) and `region_strategy_id` (`full-page`, `header-first-v1`, `cpu-default`, `stub-default`) — only these values are valid at landing; runtime free-form numeric DPI / region coordinates are forbidden on the user-facing surface.

- FR-006 / R-018.5: region-first targeting decisions deterministic and re-derivable from PDF page geometry + page index alone (no model output).
- FR-007 / R-018.7 / Clarifications Q1+Q3: deterministic fallback to full-page when whitespace-stripped concat of `blocks[].text` in targeted region on page 1 is empty; partial region-first output discarded; full-page output replaces it; document's `phase_timings.rasterization` reports combined wall-clock cost (R-018.10).
- FR-008 / FR-009 / FR-010 / FR-011: three additive top-level `run_summary` fields (`raster_profile_id`, `region_strategy_id`, `region_strategy_fallback_count`) emitted on every run including CPU/stub; absence is itself a regression signal.
- FR-014: GPU-only switches set on CPU/stub follow the warn-and-proceed pattern (warn + no behavior change + same exit status), matching features 016/017.
- FR-015: CPU and stub paths MUST NOT import GPU-only DPI / region-strategy code; imports are guarded so a host without Paddle GPU runs the default suite cleanly.
- FR-016 / FR-017 (per Clarifications Q4 carry-over from 017): two-metric quality gate — aggregate vendor-identity field score from `evaluation_run_summary.json` AND per-document pass count, both measured on the same fixed 5-doc subset, both ≥ legacy on that subset; evidence recorded in `research.md` Appendix B alongside the candidate `(raster_profile_id, region_strategy_id)` pair.
- FR-019: corpus baselines NOT regenerated.
- FR-020 / FR-022: schema_version of the four canonical stage 1 artifacts and `contract_set_version` unchanged; feature 014/015/016/017 guarantees preserved unchanged (including feature 017's `module_set_id` / `det_rec_variant_id` / `ppstructure_modules_invoked` semantics).
- FR-025: GPU verification deferral allowed per feature 016/017 precedent; deferral captured in `tasks.md` + `quickstart.md`.
- FR-026: this feature MUST NOT introduce an OCR-only fast lane; region-first still runs the existing PPStructureV3 module set on the targeted region (deferred to feature 019).
- Constitution I: pipeline / harness / model-runtime boundaries intact (this feature touches preprocessing + pipeline runtime only; harness untouched; Ollama untouched).
- Constitution II: four canonical artifact contracts unchanged. `run_summary` is run-level observability, not a stage 1 artifact contract — additive bump 0.1.4 → 0.1.5 follows the established additive pattern from feature 014 (0.1.0 → 0.1.1), feature 015 (0.1.1 → 0.1.2), feature 016 (0.1.2 → 0.1.3), feature 017 (0.1.3 → 0.1.4).
- Constitution III: spam gates / consensus comparison / explicit-vs-inferred handling / review-required decisions unchanged. The FR-007 fallback trigger is deterministic code reading `blocks[].text` per Clarifications Q3 — explicitly NOT a model decision.
- Constitution V: corpus baselines must not be regenerated (FR-019 / SC-007).

**Scale/Scope**: stage 1 corpus = 20 documents under `tests/stage1_vendor_identity/`. Benchmarking subset = the same fixed 5-doc subset feature 017 used (R-017.11; R-018.13). Single GPU-capable workstation host. Single device per process (feature 014 CF4 / feature 015 FR-006 carry over). Two named raster-profile presets at landing (`legacy`, `reduced-v1`); two named region-strategy presets at landing (`full-page`, `header-first-v1`); plus identity presets `cpu-default` and `stub-default` on both axes.

**Structure Decision**: single Python package, **two new modules** (`preprocessing/raster_profiles.py`, `preprocessing/region_strategies.py`), **one extended exception** (`UnknownPresetError.preset_axis: Literal[…]` widens to four values), **zero new exit codes** (reuses feature 017's `UNKNOWN_PRESET = 16`), **nine touched modules** (`preprocessing/rasterize.py`, `preprocessing/pipeline.py`, `preprocessing/cli.py`, `preprocessing/preflight.py`, `preprocessing/identifiers.py`, `preprocessing/errors.py`, `pipeline/timing.py`, `pipeline/corpus_run.py`, `pipeline/runner.py`, `pipeline/cli.py`). **No new top-level subpackage.** The two preset axes contract lives entirely under `preprocessing/raster_profiles.py` and `preprocessing/region_strategies.py` (the closed-vocabulary registries plus the region-strategy orchestrator), keeping the run_summary schema as the single source of truth for run-level observability. The `--raster-profile` and `--region-strategy` opt-ins live in the existing preprocess CLI and warm-corpus CLI rather than a new entry point, mirroring how feature 014 added `--preprocess-profile`, feature 016 added `--gpu-warmup`, and feature 017 added `--module-set` / `--det-rec-variant` rather than spinning up separate CLIs.
