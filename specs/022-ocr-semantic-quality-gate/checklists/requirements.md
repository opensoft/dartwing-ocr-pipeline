## Notes

This feature has known artifact-surface names that necessarily appear in the spec because they are pre-existing contracts the feature must reference precisely: `semantic_table_truth.json` (new sidecar this feature defines), `expected.json` and `preprocess_output.json` (existing artifacts), `evaluation_document.json` / `evaluation_run_summary.json` (existing evaluator reports), `document_pass_fail.vendor_identity_passed` (existing field), and features 019/020/021. Naming these is contract precision, not implementation leakage — the spec does not prescribe code structure, modules, languages, or libraries.

**All 3 [NEEDS CLARIFICATION] markers resolved** by the feature author on 2026-05-22 (recorded in the spec's Clarifications section):

- Q1 (FR-026, FR-027): canonical degraded-body fixtures live under a separate semantic-quality corpus root, not `tests/stage1_vendor_identity/`.
- Q2 (FR-002): minimum `semantic_table_truth.json` row shape is required values + row text (`row_id`, `quantity`, `description`, `unit_price`, `amount`, required row text / fragments).
- Q3 (Out of Scope, FR-033): runtime fallback/review integration is out of scope and deferred to a later feature; the semantic verdict is evaluator/report-only and MUST NOT drive runtime behavior.

The spec carries zero `[NEEDS CLARIFICATION]` markers and is ready for `/speckit.plan`.
