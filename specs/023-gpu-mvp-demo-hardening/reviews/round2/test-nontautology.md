## Tautological / weak tests

### B2 `test_phase_failure_does_not_mask_as_schema_failure` — **TAUTOLOGICAL with current fixtures**

**Why it's tautological:** `bypass_schema_validation` (used by the test, parameter at line 96) replaces `_validate_artifact` with a function that always returns `None` (conftest.py:298-301). When the stub composer fails at extraction, routing/final_payload artifacts are never written. But because `_validate_artifact` is monkey-patched away, check 7 returns `status="pass"` — not `"fail"`. The B2 fix only kicks in when check 7's `r.status == "fail"`. With the bypass, the buggy branch is unreachable.

**Recommended fix:** Either
- (a) Drop `bypass_schema_validation` from this specific test's parameters and rely on the natural failure (missing artifacts cause `_validate_artifact` to return `"file does not exist"` at schema_validation.py:46), OR
- (b) Provide a selective `_validate_artifact` stub that returns failure for missing artifacts only (mirroring `test_multi_artifact_failure` pattern at lines 50-56) AND keep that selective stub in scope.

Implementation effort: 5 minutes. Removing `bypass_schema_validation` makes the test genuinely exercise the B2 guard.

### T3 extension — **WEAK / redundant**

Already covered: the parametrized `test_skip_on_upstream_fail` (test_readiness_order.py) exercises the same generic skip loop for checks 2-6. There's no check-#1-specific code path. The added asserts about checks 7-8 being `"skipped"` are the only genuinely new coverage and could stand on their own.

**Recommended fix:** Either inline a comment that the parametrized matrix already covers the same loop (cosmetic), OR move check-#1 into the parametrize matrix in `test_skip_on_upstream_fail` to remove duplication. Not blocking.

## Sign-off

**NEEDS-ATTENTION.**

The B5 fixes (both URL tests) and T2 (successful evaluator) are genuinely non-tautological and would catch regressions of their guarded fixes. The T3 extension fills a small coverage gap at the pre→post boundary but is otherwise redundant.

The critical concern is **R2-1**: the B2 regression test is tautological because `bypass_schema_validation` (used in the test signature) neutralizes the condition the B2 fix guards. A revert of the `if runtime_outcome is None:` guard at `orchestrator.py:817` would NOT cause this test to fail. The triage doc explicitly anticipated this (line 93: "retire `bypass_schema_validation` for at least one happy-path test using a hand-crafted schema-valid stub artifact") but the recommendation was not carried out.

**Action items before merge:**

1. **R2-1 (HIGH)**: Fix the B2 test to genuinely exercise the guard. Either drop `bypass_schema_validation` (recommended — the natural file-missing failure proves the bug) or use a selective validator stub. ~5 min fix.
2. **R2-7 (HIGH→ promote)**: T7 (stub composer schema fidelity) is the root cause of R2-1; the "by design" deferral now has a concrete correctness cost. Authoring a single schema-valid stub artifact set enables R2-1 fix and unlocks future tests to retire `bypass_schema_validation`.

The B2 fix itself in production code is correct. The TEST claiming to guard it is the issue. After fixing R2-1, sign-off becomes PASS.
