# Implementation Plan: OCR-Only Fast Lane For Vendor Identity

**Branch**: `019-ocr-only-fast-lane` | **Date**: 2026-05-11 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/019-ocr-only-fast-lane/spec.md`

## Summary

Add a third closed-vocabulary preset axis on the stage 1 `ppstructurev3@gpu` preprocessing lane — `preprocess_strategy_id` — that lets operators select between the existing layout-aware `ppstructurev3` strategy and a new OCR-only fast lane (`ocr-only-v1`) that runs PaddleOCR text detection + text recognition only (no layout, table, formula, or seal modules). Activation is `--preprocess-strategy <id>` on both `python -m ledgerlinc_ocr.preprocessing` and `python -m ledgerlinc_ocr.pipeline` with env-var fallback `LEDGERLINC_PREPROCESS_STRATEGY` (CLI wins when both are set, R-019.1), mirroring feature 014's `--preprocess-profile`, feature 016's `--gpu-warmup`, feature 017's `--module-set` / `--det-rec-variant`, and feature 018's `--raster-profile` / `--region-strategy`. The feature ships at landing four `preprocess_strategy_id` values: `ppstructurev3` (the strategy active on `main` at landing time of feature 018 — the GPU-lane default until FR-016 promotion), `ocr-only-v1` (the candidate OCR-only preset), plus identity presets `cpu-default` and `stub-default` (R-019.2 / R-019.3). The feature ships **two additive top-level fields on `run_summary`** (`preprocess_strategy_id` string, `ocr_only_fallback_count` integer) emitted on every run including CPU and stub (FR-008 / FR-007 / FR-010 always-emit, mirroring feature 018's three-field bump). The codebase-level `RunSummary.SCHEMA_VERSION` patches **0.1.5 → 0.1.6** for the two additive top-level fields (R-019.14); the four canonical stage 1 artifact schemas, `contract_set_version`, and the `pipeline_version` shape are unchanged (FR-019 / FR-020 / SC-011). Combining `--preprocess-strategy` with `ppstructurev3@cpu` or any stub adapter emits a clear stderr warning (FR-013 warn-and-proceed pattern, identical structure to feature 016/017/018 precedent) and otherwise produces a run identical to one without the flag. Selecting an unknown identifier value (e.g., `--preprocess-strategy ocr-only-v99`) fails fast with **the existing exit code 16** (`UNKNOWN_PRESET`) and a clear stderr message — the existing `UnknownPresetError` from feature 017 is extended additively (its `preset_axis: Literal[...]` gains `"preprocess_strategy"` — five values now); R-019.12 covers the wiring. The FR-005 OCR-only → `ppstructurev3` per-document fallback (Clarifications Session 2026-05-11 Q1 candidate-with-fallback, Q2 combined two-threshold check) is implemented deterministically: after OCR-only preprocessing of a document, if **either** the aggregate non-whitespace token count across the targeted region's OCR output is below `OCR_ONLY_MIN_TOKEN_COUNT = 8` (R-019.5) **OR** the mean detector confidence across detected boxes is below `OCR_ONLY_MIN_CONFIDENCE_MEAN = 0.60` (R-019.6 — mean is the chosen aggregation function per R-019.6), the partial OCR-only output for that document is discarded and the document is re-preprocessed under the `ppstructurev3` strategy on the **same** PPStructureV3 engine instance for that run (preserving feature 015 FR-001 single-engine guarantee — R-019.10), the document's per-document `phase_timings.rasterization` and `phase_timings.per_page_inference` report the combined wall-clock cost (R-019.10), and the run-level `ocr_only_fallback_count` is incremented by exactly 1 for that document. The zero-detection edge (no OCR boxes detected on the targeted region) is treated as a sufficiency-fail (R-019.7) — the document falls back deterministically. The OCR-only path is implemented by a sibling singleton engine (`paddleocr.PaddleOCR(...)` via a new `preprocessing/ocr_only.py` module) running on the same `gpu:0` device the PPStructureV3 engine binds; the two engines coexist in the same process under independent single-construction guarantees so an OCR-only-only run never constructs PPStructureV3 and a `ppstructurev3`-only run never constructs the OCR-only engine (R-019.10). OCR-only `blocks[]` are reassembled deterministically from PaddleOCR lines by Y-axis line clustering (R-019.8) into the existing `blocks[]` shape with `block_type = "text"`; coordinate origin / units / page index / `pages.length == page_count` invariants are preserved identically to a `ppstructurev3` run on the same fixture (FR-003). The OCR-only path composes orthogonally with feature 018's `region_strategy_id` axis (FR-026) — when `region_strategy_id = header-first-v1` is active, the OCR-only pass rasterizes only the header band on page 1 and detects+recognizes on that crop, pages 2..N appear as empty records per feature 018 Q2; when the OCR-only check trips and falls back to `ppstructurev3`, the fallback preserves the active `region_strategy_id` (so a `(header-first-v1, ocr-only-v1)` run that falls back lands `(header-first-v1, ppstructurev3)` on that document); feature 018's `region_strategy_fallback_count` axis fallback is independent and can still fire on the fallen-back document (R-019.11). All feature 014 / 015 / 016 / 017 / 018 guarantees (single-engine-per-process *when invoked*, GPU-readiness probed at most once, single-device guard, no silent CPU fallback after `ppstructurev3@gpu` is selected, warmup behavior under `--gpu-warmup` unchanged, `pipeline_version` ends in `.gpu0`/`.cpu0`, feature 017's `module_set_id` / `det_rec_variant_id` / `ppstructure_modules_invoked` semantics unchanged, feature 018's `raster_profile_id` / `region_strategy_id` / `region_strategy_fallback_count` semantics unchanged) carry over unchanged (FR-022); the `feature 015 FR-001 "exactly once per process"` exception explicitly permits PPStructureV3 to remain unconstructed when `preprocess_strategy_id = ocr-only-v1` with no fallbacks (R-019.10). Corpus baselines and `preprocess_output.json` shape are byte-identical to `main` for the legacy `(legacy, full-page, ppstructurev3)` GPU configuration (FR-019 / SC-007 / SC-008). The FR-015 benchmark — `ppstructurev3` baseline plus at least the `ocr-only-v1` candidate — runs over the **same fixed 5-document subset that features 017 and 018 used** (`inv_001_easy`, `inv_002_easy`, plus the three from R-017.11 / R-018.13; R-019.13) and lands its numbers in this feature's `quickstart.md` Appendix A. Quality-gate evidence (FR-016 / FR-017) — both metrics from the existing evaluator (per-corpus aggregate vendor-identity field score from `evaluation_run_summary.json` AND per-document pass count per `docs/stage1-vendor-identity/scoring.md`) — lands in this feature's `research.md` Appendix B alongside the candidate `preprocess_strategy_id` value and the active `(raster_profile_id, region_strategy_id)` pair. GPU verification of FR-015 / FR-016 / GPU-marked tests may be deferred per FR-025 (feature 016/017/018 precedent); the deferral is captured in `tasks.md` and `quickstart.md` Appendix B so the verification cannot be quietly skipped.

## Technical Context

**Language/Version**: Python 3.12 (matches `.devcontainer/Dockerfile` base image and `pyproject.toml requires-python = ">=3.12"`).
**Primary Dependencies**: existing only — `paddleocr>=3.5,<4` (the `PaddleOCR` class is exposed alongside `PPStructureV3` in the same package; OCR-only runs use the former — R-019.10), `paddlepaddle-dcu` (workstation-only optional install, already proven in features 014–018), `pypdfium2>=4.30,<5`, `Pillow>=10.4,<11`, `numpy>=1.26,<3`, `jsonschema>=4.22,<5`, `pydantic>=2.7,<3`. **No new pinned dependency.** ROCm/MIOpen/COMGR are workstation system dependencies, not Python packages. The OCR-only path reuses feature 017's `det_rec_variant_id` text-detection / text-recognition variants (per FR-027 — no new model, no new download host).
**Storage**: filesystem only. Reads `tests/stage1_vendor_identity/inv_XXX_<difficulty>/source.pdf` (unchanged). Writes `preprocess_output.json` into the same per-document folder unchanged in shape (FR-003 / FR-020). The two new `run_summary` fields live exclusively in the existing `kind: "run_summary"` stdout line per feature 014/015/016/017/018 lineage; **no new persisted artifact** (FR-021 / Out of Scope). The FR-015 benchmark numbers and FR-016 quality-gate evidence land in this feature's `quickstart.md` Appendix A (benchmark numbers) and `research.md` Appendix B (quality-gate evidence) at landing time; both are Markdown documents under `specs/019-ocr-only-fast-lane/`, not under `contracts/` and not under `tests/stage1_vendor_identity/`.
**Testing**: pytest. Existing markers `gpu` (deselected without GPU per FR-023) and `live` carry over. New tests under `tests/unit/preprocessing/` and `tests/pipeline_tests/` (matching feature 016/017/018's directory convention; `tasks.md` is normative for exact file paths). Existing `tests/contract_tests/` continue to pass unchanged (FR-020). Stub-adapter and CPU-only suites must continue to pass without GPU (FR-014 / FR-024 / SC-006). The warn-and-proceed path for the new switch is covered on the default (no-GPU) suite per FR-024.
**Target Platform**: Linux (devcontainer + workstation WSL with native ROCm `gfx1151` via host Ollama / `.venv-paddle-rocm`). CPU fallback works on any Linux host. Production CI exercises CPU + stub only.
**Project Type**: single Python package (`ledgerlinc-ocr`) with pluggable preprocess strategies. **Three new modules** (`preprocessing/preprocess_strategies.py`, `preprocessing/preprocess_strategy_optin.py`, `preprocessing/ocr_only.py`), **one extended exception** (`UnknownPresetError.preset_axis: Literal[…]` widens to five values), **zero new exit codes** (reuses feature 017's `UNKNOWN_PRESET = 16`), and **surgical edits to nine existing modules** (`preprocessing/pipeline.py`, `preprocessing/cli.py`, `preprocessing/preflight.py`, `preprocessing/identifiers.py`, `preprocessing/errors.py`, `pipeline/timing.py`, `pipeline/corpus_run.py`, `pipeline/runner.py`, `pipeline/cli.py`).
**Performance Goals**: no numeric latency target (Constitution: "no latency target as a release gate"; spec Assumptions). Outcomes are observability + measurable reduction in `phase_timings.per_page_inference` on the OCR-only path (text-det + text-rec only vs. full PPStructureV3 layout pipeline) — measurable as (a) `phase_timings.per_page_inference` strictly lower on `ocr-only-v1` vs `ppstructurev3` for the same fixture without any fallback (SC-001 / SC-003); (b) the FR-015 benchmark is recorded with both quality metrics (SC-003); (c) `preprocess_strategy_id` differs across configurations and remains stable within a configuration (SC-004); (d) `ocr_only_fallback_count` is non-negative, ≤ corpus subset size, and reproducible across runs of the same `(preprocess_strategy_id, raster_profile_id, region_strategy_id)` × corpus subset (R-019.11).
**Constraints**:
- FR-001: closed-vocabulary `preprocess_strategy_id` (`ppstructurev3`, `ocr-only-v1`, `cpu-default`, `stub-default`) at landing. On the user-facing CLI/env surface, only `ppstructurev3` and `ocr-only-v1` are selectable; `cpu-default` / `stub-default` are internal identity values emitted on non-GPU profiles. Runtime free-form module selection is forbidden.

- FR-003: `preprocess_output.json` field shape, page count, page index, coordinate origin / units, block-index ordering rules, and `pages.length == page_count` invariant identical to a `ppstructurev3` run on the same fixture.
- FR-005 / Clarifications Q2: deterministic combined two-threshold trigger — `(token_count >= OCR_ONLY_MIN_TOKEN_COUNT) AND (mean_confidence >= OCR_ONLY_MIN_CONFIDENCE_MEAN)` for sufficiency; if either trips, fall back to `ppstructurev3` on that document. Trigger is re-derivable from preprocessing-pass inputs alone (R-019.5 / R-019.6 / R-019.7).
- FR-006: trigger decision derivable from preprocessing-pass inputs alone (page geometry, rasterized page metadata, OCR-only detector / recognizer output); no extraction or vendor-identity model output participates.
- FR-007 / FR-008 / FR-010: two additive top-level `run_summary` fields (`preprocess_strategy_id`, `ocr_only_fallback_count`) emitted on every run including CPU/stub; absence is itself a regression signal.
- FR-013: GPU-only switch set on CPU/stub follows the warn-and-proceed pattern (warn + no behavior change + same exit status), matching features 016/017/018.
- FR-014: CPU and stub paths MUST NOT import GPU-only OCR-only-strategy code; imports are guarded so a host without Paddle GPU runs the default suite cleanly.
- FR-016 / FR-017 (mirroring feature 018's FR-016 / feature 017's FR-015): two-metric quality gate — aggregate vendor-identity field score from `evaluation_run_summary.json` AND per-document pass count, both measured on the same fixed 5-doc subset, both ≥ legacy on that subset; evidence recorded in `research.md` Appendix B alongside the candidate's `preprocess_strategy_id` value.
- FR-019: corpus baselines NOT regenerated.
- FR-020 / FR-022: schema_version of the four canonical stage 1 artifacts and `contract_set_version` unchanged; feature 014/015/016/017/018 guarantees preserved unchanged.
- FR-025: GPU verification deferral allowed per feature 016/017/018 precedent; deferral captured in `tasks.md` + `quickstart.md`.
- FR-026: OCR-only and feature 018's region-strategy axis compose orthogonally; OCR-only fallback on a document preserves the active `region_strategy_id`; feature 018's region-strategy-side fallback (region-first → full-page) remains independent and may still fire on the fallen-back document.
- FR-027: no new OCR engine; OCR-only reuses the same `det_rec_variant_id` text-det / text-rec variants exposed by feature 017.
- Constitution I: pipeline / harness / model-runtime boundaries intact (this feature touches preprocessing + pipeline runtime only; harness untouched; Ollama untouched).

- Constitution III: spam gates / consensus comparison / explicit-vs-inferred handling / review-required decisions unchanged. The FR-005 fallback trigger is deterministic code reading PaddleOCR det+rec output per Clarifications Q2 — explicitly NOT a model decision.
- Constitution V: corpus baselines must not be regenerated (FR-019 / SC-007).

**Scale/Scope**: stage 1 corpus = 20 documents under `tests/stage1_vendor_identity/`. Benchmarking subset = the same fixed 5-doc subset features 017 and 018 used (R-017.11; R-018.13; R-019.13). Single GPU-capable workstation host. Single device per process (feature 014 CF4 / feature 015 FR-006 carry over). **Structure Decision**: single Python package, **three new modules** (`preprocessing/preprocess_strategies.py`, `preprocessing/preprocess_strategy_optin.py`, `preprocessing/ocr_only.py`), **one extended exception** (`UnknownPresetError.preset_axis: Literal[…]` widens to five values), **zero new exit codes** (reuses feature 017's `UNKNOWN_PRESET = 16`), **nine touched modules** (`preprocessing/pipeline.py`, `preprocessing/cli.py`, `preprocessing/preflight.py`, `preprocessing/identifiers.py`, `preprocessing/errors.py`, `pipeline/timing.py`, `pipeline/corpus_run.py`, `pipeline/runner.py`, `pipeline/cli.py`). **No new top-level subpackage.** The preprocess-strategy axis contract lives entirely under `preprocessing/preprocess_strategies.py` + `preprocessing/preprocess_strategy_optin.py` + `preprocessing/ocr_only.py` (closed-vocabulary registry, env-var resolution, and the OCR-only orchestration including the FR-005 combined-trigger eligibility check), keeping the run_summary schema as the single source of truth for run-level observability. The `--preprocess-strategy` opt-in lives in the existing preprocess CLI and warm-corpus CLI rather than a new entry point, mirroring how features 014–018 added their orthogonal switches rather than spinning up separate CLIs.
